# 微信公众号草稿箱上传

## 边界

草稿箱上传是完整本地发布包之后的可选阶段。只有用户明确要求“上传草稿箱”“保存到公众号后台”或同等意思时执行。

只保存草稿，不执行群发、正式发表、定时发表或发送给关注者。用户说“发布到公众号后台”时，默认解释为保存草稿；若用户明确要求正式发表或群发，停止并说明本 Skill 不执行该动作。

## 前置条件

1. 本地发布包已通过 `PACKAGE_OK`。
2. 原始文件哈希未变化。
3. 已安装 `baoyu-post-to-wechat`。
4. Bun 与 Chrome 可用。
5. 用户已在操作时确认把最终文章和图片上传到指定公众号账户。

存在多个公众号账户时，先让用户选择账户。不要从作者名、文章主题或历史会话猜测账户。

## 身份字段

按以下优先级解析作者或编辑者：

1. 当前请求明确提供的名字；
2. 派生 Markdown 的 frontmatter；
3. `baoyu-post-to-wechat` 所选账户的配置；
4. 留空。

不得把 Skill 作者身份、`Jiaojie` 或其他名字硬编码为公开默认值。不得为缺失身份编造署名。

## 执行

1. 展示账户、文章标题、图片数量和“仅保存草稿”的动作摘要。
2. 取得一次操作确认。
3. 使用 `baoyu-post-to-wechat` 的当前文章发布工作流。
4. 传入派生 Markdown，让发布 Skill 自己处理图片和排版；不要传入预转换 HTML。
5. 需要登录时，让用户在专用 Chrome 窗口扫码，登录后继续。
6. 停止在草稿保存，不进入群发或正式发表流程。

## 结果验证

以下任一情况发生时，不得声称自动保存成功：

- 保存按钮被点击，但后台没有返回可靠结果；
- 页面仍停留在新建编辑 URL，且没有草稿标识；
- 编辑页关闭或消失，但草稿箱未核实；
- 用户在脚本等待期间手动点击了保存；
- 只观察到 `appmsgid`，但无法区分是脚本还是用户触发保存。

若用户手动介入，报告“内容由代理填入，草稿由用户手动保存”。若保存无法验证，保留本地发布包并请用户在草稿箱按标题确认。

## 失败降级

- 网络或代理失败：停止上传，保留本地包，不修改代理规则；给出最小恢复步骤。
- 登录失败：让用户扫码，不读取或导出 Cookie、密码或会话文件。
- 自动保存失败：尽量保留已填充编辑器供用户手动保存；不要重复创建多个草稿。
- 编辑页丢失：重新填充前先说明可能产生重复草稿，并让用户核对草稿箱。
