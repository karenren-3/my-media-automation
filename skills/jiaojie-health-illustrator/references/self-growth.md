# 自我成长与偏好积累

## 三类行为

- **A 类：任务复盘（默认开启）**：每次任务结束后，在发布包中写入 `growth/retrospective.md`。即使任务失败，也记录失败阶段、证据和未验证项。
- **B 类：本地偏好积累（默认开启）**：从复盘中提取候选偏好，例如配图数量、比例、色彩、语气、免责声明策略和草稿箱设置。候选项必须标记 `待确认`；只有用户明确确认后，才能作为后续任务的默认偏好。偏好文件只保存在本机，不进入公开发布包或 GitHub。
- **C 类：公开 Skill 成长（严格确认）**：把候选偏好或复盘结论写入公开 Skill、提交 GitHub 或创建版本发布前，必须先展示：拟修改规则、证据来源、影响文件、兼容性风险和版本方案。只有用户明确回复“确认”后才能执行；“继续”“可以”“看起来不错”等不视为 C 类确认，除非明确指向该公开变更。

## 复盘格式

```markdown
# 任务复盘

## 结果
- 状态：完成 / 部分完成 / 失败
- 文章主题：
- 使用的已确认偏好：

## 证据与问题
- 健康表述：事实、风险、待专业复核项
- 配图：数量、比例、中文标签、视觉一致性
- 排版与文件：Markdown、HTML、ZIP、图片引用
- 验证与发布：PACKAGE_OK、草稿保存状态、未验证项

## 候选偏好（默认待确认）
- 观察：
- 证据：
- 建议规则：
- 确认状态：待确认

## 下次行动
- 
```

## 隐私与关闭

- 不记录正文、密码、Cookie、Token、会话信息或不必要的个人健康信息。
- 不自动上传复盘或偏好。
- 用户说“本次不记录成长数据”时，完成任务但不写入复盘和偏好。
- 公开版本升级必须走 C 类确认，不得在普通任务中静默修改 Skill。
