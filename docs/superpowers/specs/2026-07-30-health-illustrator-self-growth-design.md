# Jiaojie Health Illustrator 自我成长功能设计

## 目标

让 Skill 在每次健康科普公众号任务后自动复盘，并在本机逐步沉淀已确认的用户偏好，同时保持公开 Skill、文章内容和账号凭据不被自动改写或上传。

## 范围

1. 每个完成的发布包可生成 `growth/retrospective.md`，覆盖健康表述、配图、排版、文件验证和草稿箱保存五类检查。
2. 本机维护用户偏好记录，只收录用户明确确认过的偏好；每条记录包含来源、证据和确认状态。
3. 支持“本次不记录成长数据”临时关闭复盘。
4. 公开 Skill 的改进只生成候选建议。任何将候选建议升级为公开 Skill 内容、提交或发布的动作，都必须先向用户说明变更内容、影响范围和版本方案，并取得用户明确回复“确认”后，才以版本化更新方式执行。

## 数据边界

- 不记录文章正文、账号密码、Cookie、Token、会话信息或未脱敏的个人健康信息。
- 复盘和偏好默认只保存在本机；不自动上传到 GitHub、微信或其他服务。
- 未经确认的观察只能作为候选建议，不能成为默认规则。
- C 类“公开成长”：必须经过用户明确确认；没有确认时，不修改公开 Skill、不提交 GitHub、不创建发布版本。

## 工作流

任务完成后：生成复盘 → 提取候选偏好 → 标注“待确认” → 下次运行时仅应用“已确认”偏好 → 报告本次使用了哪些偏好。若用户提出公开升级，再单独展示 C 类变更提案并等待明确确认。

失败任务也可生成复盘，但必须标记失败阶段和未验证项，不能把失败结果写成已完成。

## 验证

- Skill 结构校验通过。
- 现有发布包验证测试保持通过。
- 文档明确 A+B 的默认行为、关闭方式、隐私边界和公开版本升级门槛。
- 文档明确 C 类公开升级的确认门槛：必须得到用户明确“确认”。
